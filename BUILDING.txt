
Git workflow
The first contribution commit adds DIR BREAK and DOS history, documentation,
and regression tests. The second adds this Windows/Visual Studio build setup.
The author's existing commit history is preserved. Build output, downloaded
tools, and personal Visual Studio settings are excluded from Git.

November 4 data-bank migration
The current branch incorporates upstream c26463b. PICO-WORK.z is removed.
History uses PAGE_CALL/VIRTUAL_ROUTINE for code bank 183 and VIRTUAL_DATA for
data banks 33-35. $37E0-$37FF remain reserved for hardware.
Compared with the previously tested 655970e feature build, three compiled
files change: SYS/SYSP.sys, SYS/SYS0.sys, and SYS/overlayl.sys. Keep these
matched when testing; the former two-file feature-only instructions do not
cover this upstream loader/memory change. SYS/overlayd.sys is unchanged.
Back up the three existing files before copying this build's versions.
Re-test DIR/BREAK, command recall/editing, BASIC DEF USR/FN, and loading a CMD
program, because the upstream change relocates the binary loader too.

Software settings configuration
Normal startup remains unchanged. HistorySize is read once on first DOS input
from /SYS/settings.cfg, using bounded I/O waits and a 16 KiB input limit.
Default 8; supported range 1-20. Code pages 183-184 and data pages 33-39
are reserved for history and configuration.

To test this update, back up and replace SYS/SYSP.sys and copy SYS/settings.cfg
from build/SD-CARD to the SD card. Keep the working HARDWARE.cfg, which now
contains hardware options only. Remove its old HistorySize entry if present.
Set HistorySize = 20 in settings.cfg, reboot, and test recall beyond eight
commands. Missing settings.cfg defaults to eight. Re-test DIR/BREAK too.

Build/Rebuild stages both configuration files. Preserve your card's hardware
settings when deploying; do not replace HARDWARE.cfg with generic defaults.
No Pico firmware changes are included. Leave changes uncommitted until
physical hardware testing passes.

Sequential BASIC file I/O - combined branch hardware test
This addition changes SYS/SYSP.sys. It adds OPEN, CLOSE, PRINT#, INPUT#,
LINE INPUT# and EOF for three sequential files on Floppy80. It does not change
the Pico firmware or require configuration changes. See USERGUIDE.md.

1. Build the current branch in Visual Studio. Back up the working SD-card
   SYS/SYSP.sys, then replace it with build/SD-CARD/SYS/SYSP.sys.
2. Copy build/SD-CARD/IOCHECK.BAS to the SD-card root. This tokenized test
   file is generated by tests/test_basic_io.py, not the normal build. If it
   is absent, run that test as documented in tests/README.txt, or enter the
   numbered listing in tests/IOCHECK.txt manually at the BASIC prompt.
3. Boot the Model I, use the SD-card root as the current directory, then:
     LOAD "IOCHECK.BAS"
     RUN
   Expected result: BASIC FILE I/O PASS.
   The program creates/replaces IOTEST.DAT, IOCOPY.DAT and IOTHIRD.DAT in the
   current directory. Use a test directory if those names already matter.
4. Repeat RUN. Power off after the program ends, inspect the three text files
   on the PC, then reboot and re-test DIR/BREAK and command history.

IOTEST.DAT should contain HELLO FLOPPY80 and a second line with 123 and 4.25.
IOCOPY.DAT should contain HELLO FLOPPY80; IOTHIRD.DAT should contain 123 and
4.25. Numbers use BASIC's normal surrounding spaces; lines use CR/LF.
The smoke program verifies repeated EOF checks, integer/double input, full
line input, three open files, CLOSE, reopen and automatic close on END.

Software tests simulate the Pico protocol. Passing those tests is not a
substitute for this first physical-board test. Leave changes uncommitted
until that test passes.
BASIC CMD - merged with sequential file I/O
This branch includes both features. The CMD revision adds the returning
DOS @CMNDI API to SYS0 and
consolidates CMD into code page 179, with data page 41 for copied text.
SYS/SYSP.sys contains the paged implementation. The unpaged core and affected
overlays also change: SYS/SYS0.sys, SYS/overlayb.sys, SYS/overlayc.sys and
SYS/overlaye.sys. Keep all five SYS files matched when deploying this revision.
The returning API is compiled in both modes; automated execution tests use
the paged build. No Pico firmware
or configuration changes are needed. Assembly uses 8-column tab stops.

After building, back up the working SD-card SYS/SYSP.sys and replace it with
build/SD-CARD/SYS/SYSP.sys. First verify LOAD and RUN of a known BASIC program.
Then test CMD "DIR" and CMD "PWD" at the BASIC prompt, and within a program.

For the included test, copy CMDCHECK.BAS and CMDTEST.TMP from build/SD-CARD to
the same directory on the card. Select that directory, then enter:
  LOAD "CMDCHECK.BAS"
  RUN
The program lists CMDTEST.TMP, deletes it through CMD DEL, lists again, and prints
CMD TEST FINISHED. Only the provided disposable CMDTEST.TMP is targeted.
Copy CMDTEST.TMP back before repeating; otherwise File not found is expected.
The test artifacts are generated by tests/test_basic_commands.py; see
tests/README.txt. CMD LOAD now loads binary records and resumes BASIC;
external command names remain unsupported. USERGUIDE.md explains the limits.

Re-test DIR/BREAK and history at the DOS prompt. Commit only after physical
hardware testing. Both features are included in this build.
I/O uses code pages 160-178 and data pages 1-3/40; CMD uses code page
179 and data page 41. The allocations do not overlap.
